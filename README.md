# 镜界 JINGJIE · AI 智美形象管家

一面会思考的落地镜。一次全身人像采集，同步完成 **AI 体态风险筛查** + **面部美学诊断**，
输出矫正、穿搭、妆容、饮食、运动、作息全套个性化方案。

高保真交互原型，**零外部依赖**（纯原生 HTML/CSS/JS，无框架、无 CDN）。

---

## 一、运行方式

摄像头 API 要求**安全上下文**（`https://` 或 `localhost`），`file://` 无法授权。因此必须用 HTTP 打开：

```bash
cd jingjie-demo
python -m http.server 8899
# 浏览器打开 http://127.0.0.1:8899/index.html
```

> 若只想看页面效果、不用摄像头，也可直接双击 `index.html`（会降级为剪影演示模式）。

`gallery.html` 是全部页面截图的汇总总览，可直接双击打开。

## 三、真实摄像头分析链路

### 1. 采集
`getUserMedia({ video: { width: 1280, height: 960, frameRate: 30 } })`
→ 首帧需**用户手势**（浏览器策略），故拍摄页设计为「点击开启摄像头」。
→ 9 秒超时 + 静默自动重试一次（应对偶发挂起）。

### 2. 实时跟踪（8 fps）
`Camera.startLoop()` 每 125ms 抽 160×120 低分辨率帧 → 肤色像素投影求包围盒
→ CSS 平滑跟随（0.35 插值）叠加青色检测框，同步刷新亮度 / 清晰度 / 人脸状态。

### 3. 肤色检测（YCbCr 阈值法）
```
Y  = 0.299R + 0.587G + 0.114B
Cb = -0.169R - 0.331G + 0.500B + 128     要求 77 ≤ Cb ≤ 127
Cr =  0.500R - 0.419G - 0.081B + 128     要求 133 ≤ Cr ≤ 173
附加约束：R > G、R > B、max-min ≥ 12、60 < R ≤ 250   （排除木质/暖色墙面）
```

### 4. 人脸包围盒
肤色像素列/行投影 → 各取累积 5%~95% 主区间（抗噪）→ 归一化。
有效条件：肤色占比 1.2%~65%，且不能横纵同时占满 96%（排除纯色背景）。

### 5. 冷暖判定
```
hueScore = (平均色相 - 25) × 1.8
rbScore  = (平均R-B - 38) × 0.9        （典型中性肤色 R-B ≈ 38）
冷暖指数  = clamp((hueScore + rbScore) / 2, -50, +50)     正暖负冷
≤ -12 冷调 ／ ≥ +12 暖调 ／ 其余 中性调
```

### 6. 质量评估
- 亮度：灰度均值（< 58 偏暗 / > 205 过曝）
- 对比度：灰度标准差（< 26 偏低）
- 清晰度：**拉普拉斯方差**（4 邻域，< 7 偏模糊）
- 暗部/高光占比（< 38 灰阶 / > 232 灰阶）

### 7. 多帧融合
快门连抓 5 帧，对肤色 RGB / 明度 / 饱和度 / 冷暖指数**取中位数**，抗单帧抖动。

## 四、建议引擎（advisor.js）

```
肤色冷暖 ──┬─→ 配色知识库 PALETTES{cool,neutral,warm}
           │      → 主色色卡 / 规避色 / 金属 / 唇色 / 眼影 / 发色
           └─→ 明度+饱和度 → 四季细分（春/夏/秋/冬型）

脸型比例 ──┬─→ FACE_ADVICE  {鹅蛋/圆/长形/方/横长}   （女生：发型 / 配饰 / 妆容）
           └─→ FACE_ADVICE_M{鹅蛋/圆/长形/方/横长}   （男生：发型 / 配饰 / 修饰）

性别 ────────→ 决定走 妆容 分支（唇色/眼影）还是 理容 分支（护肤/胡须/眉形）

体态偏移 ──→ POSTURE_DIET{forward_head, shoulder, pelvis}
           → 饮食（维D+钙 / Omega-3 / 控糖控咖啡因…）
           → 运动（收下巴 / 胸椎伸展 / 肩胛稳定…）
           → 作息（屏幕齐眼 / 每小时起身 / 23:30 前入睡…）

环境质量 ──→ 补光 / 距离 / 对比度 实拍诊断
```

同一用户在不同光照下采集结果不同，**非预置文案**。
`Advisor.build(analysis, posture, gender)` 第三个参数决定文案分支，
返回值中带 `gender` 字段供渲染层判断。

## 五、男生 / 女生双主题

一键切换整套视觉与文案，**同一个页面零重载换肤**。

**实现方式**：所有颜色收敛为 CSS 变量，主题只是变量覆盖。

```
:root[data-gender="male"]   → --c-accent:#7ee8dd（青） 背景 #05070d
:root[data-gender="female"] → --c-accent:#ff8fb8（粉） 背景 #0d060c
                              --c-accent-rgb / --g-brand / --c-border / --c-text …
```

切换入口（两处，共用 `J.setGender()`）：

| 位置 | 控件 |
|---|---|
| 左侧品牌区 | `.gs-seg` 分段开关「♂ 男生 / ♀ 女生」 |
| 手机屏内右上 | `.gender-pill` 图标胶囊 |

同步改变的内容：

- **配色**：舞台光晕、极光背景、手机金属边框（转玫瑰金）、头像、主按钮、卡片描边、文字色
- **图标文字**：头像字样 `镜` ⇄ `她`；报告区块标题 `妆容` ⇄ `理容`、`发型与配饰建议` ⇄ `发型与理容建议`、图标 `💄` ⇄ `🧔`
- **建议文案**：女生输出唇色 / 眼影 / 发色色号；男生输出护肤 / 胡须 / 眉形要点，穿搭措辞改为衬衫外套表达
- **持久化**：写入 `localStorage['jingjie.gender']`，刷新后保持；也支持 `?gender=female` URL 参数

**两个易踩的坑**（已修复）：

1. `:root` 与 `body` 是**不同元素**。只给 `body` 设 `data-gender`，变量不会作用于
   `html` 自身（canvas / 滚动条 / 表单控件会漏色）。必须同时挂到 `document.documentElement`，
   且 CSS 选择器写成 `:root[data-gender="female"], body[data-gender="female"]`。
2. 滑块位移不能用 CSS `translateX(100%)` —— 「男生 / 女生」两词宽度不同，100% 会错位，
   且会覆盖 JS 内联 transform。统一由 `syncThumb()` 按实际 `getBoundingClientRect()` 计算，
   并在字体加载完成 / `load` / `resize` 后重算。

## 七、无头浏览器验证（Edge + CDP）

用 `--use-fake-device-for-media-stream` + `--use-file-for-fake-video-capture=fakeface.y4m`
喂入合成人像，走完「开摄像头 → 实时跟踪 → 快门 → 报告」全链路。

关键点（踩坑记录）：
1. Edge 进程必须 `subprocess.Popen(..., creationflags=DETACHED_PROCESS)` 才能存活。
2. 必须显式 `Page.navigate`，否则 target 停在 `about:blank`。
3. 必须 `Page.setCacheDisabled`，否则改动不生效。
4. **`const CamUI = ...` 不会挂到 `window`**，跨脚本引用要用 `typeof CamUI !== 'undefined'`。
5. `Target.activateTarget` + `Page.bringToFront` 避免后台节流。
6. `Page.captureScreenshot` 用 CDP 而非 `--screenshot`（后者静默失败）。

实测结果：肤色 RGB(196,153,125)、冷暖 +13（暖调）、脸型长形脸、
单帧有效肤色像素 20,640 个、置信度 96%、JS 报错 0。

## 八、已知边界

- 肤色检测是**启发式**，强逆光 / 红墙 / 木质背景可能误检；已用质量分与置信度提示。
- 体态关键点目前仍为原型演示数据（未接入姿态估计模型），肤色与脸型为真实计算。
- 脸型由面部框长宽比近似推断，非真实 68 点轮廓拟合。
- 健康建议为通用科普性内容，**不构成医疗建议**。
- 性别主题只改变配色与建议措辞，**不改变分析算法**（肤色 / 脸型判定与性别无关）。
